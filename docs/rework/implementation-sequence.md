# V1 rework implementation sequence

This is the sequence for future authorized work, not permission to implement it in R0. Agent 00 manages [ledger](rework-ledger.md) and exact write reservations. Before every UI slice: Agent 02 audits current live/repository contracts and publishes the role/lifecycle matrix; Agent 01 queries the matching Stitch screens and provides a design contract. After every slice: Agent 10 verifies the integration gate before the next phase starts. PENDING or BLOCKED is not PASS.

Keep the requested order. R6 consumes the **existing** Guest Program projection; R7 later reworks its operational linkage. It does not require pulling Guest Program ownership into Agent 08 or moving R7 ahead. R3 Home and R5 finance rely on existing canonical aggregates; they must not reimplement downstream domains.

## Contract-change gate

A future backend change requires: current insufficiency, semantic owner agreement, forward-only plan, backward compatibility, RLS/constraints/indexes/grants, generated-type plan, local and authorized DEV tests, advisor review and recovery plan. Agent 02 implements it; 00 serializes it before clients consume it. R0 never applies the snapshot migration. Changes to a shared UI primitive go to 01; root navigation/session changes go to 03.

## Slice completion

Handoff includes changed files, contracts used, migration/no migration, Stitch IDs, deviations, test evidence, limitations, blockers and recommended next task. Agent 10 records gate PASS/PENDING/BLOCKED with tested commit/device/build. Agent 00 updates the ledger and names the next authorized agent. Fixes stay in owning domains; do not bundle unrelated fixes or promote a preserved WIP set without re-audit. Release requires all gates and no automatic merge/deployment.
