# Mobile couple onboarding visual and contract review

Reviewed against the actual Stitch screenshots and HTML structure from **Katipan Wedding Planner UI System** on 2026-09-27. The five references are Welcome `40853f07b29042cdb22c49d5bd778dd4`, Create Our Wedding `d53e9d8d88584c57b5e9999fe1f2fe48`, Couple & Wedding Details `f12a02d5acfa435f97c8263961825b61`, Wedding Motif & Onboarding Complete `cc9eb4285dd846fea49152bcc8c4f6e6`, and Invite My Katipan `586c03b4559547ff994754a861b689ce`.

The Expo web render was compared with each Stitch screenshot. The local headless Edge renderer has a 500 CSS pixel minimum viewport, so that comparison covers the layout and hierarchy at 500 pixels; native iOS and Android were export checked but not visually inspected in simulators. The same bundled editorial imagery and Warm Editorial Nuptial colors, fonts, rounded cards, pill actions, and progress treatment are used. Welcome was adjusted after review to soften the photograph edge and wrap feature labels.

Intentional adaptations:

- Email/password authentication has no Stitch screen. It uses Welcome imagery and shared fields/buttons. Account confirmation follows Supabase Auth settings.
- The Details screen adds an editable Wedding workspace name and ceremony style because `create_couple_wedding` requires the first and supports the second. The Stitch guest ranges map to representative planning counts (25, 75, 125, 200, 250) with a visible explanation. The date uses a validated ISO input instead of Stitch's web calendar control for consistent native keyboard behavior. A date may remain undecided.
- Stitch's optional target budget has no Wedding-wide creation field. It is explicitly labeled **preview only**, held only in the in-memory draft, and excluded from the RPC. Budget setup belongs to the later finance slice. The Stitch copy that claimed automatic saving was replaced with the true creation moment.
- Motif title and color swatches persist through authorized `wedding_motifs` and `motif_colors` access. The Stitch cover photograph is bundled as an editorial preview. Changing or uploading a cover through Attachment/Storage is deferred; this screen does not imply that the image was saved to the Wedding. The completion CTA advances to partner invitation because the Wedding dashboard is not in this UI slice. The example budget badge was omitted because there is no persisted target value.
- Invitation issuance targets the existing second Partner Person and opens the native/web share sheet with a one-time `katipan:///accept-invitation?token=...` link. The receiving route is a small Warm Editorial adaptation needed for that link to resolve and uses the existing `accept_wedding_invitation` RPC. The raw token is never logged or saved to local or database storage. Pending state stores only invitation metadata. Stitch's channel-specific Messenger/Viber buttons are replaced by the platform share sheet.
- Stitch's entry for joining an existing invited workspace on Create Our Wedding is deferred to the receiving invitation route. Partner invitation can be skipped; the planning dashboard will be the next UI slice.

DEV migrations match the 19 repository migration versions. The relevant typed RPC signatures and authorized motif tables match DEV. No schema change was needed. A rollback-only authenticated DEV smoke transaction created a couple Wedding and issued a Partner invitation, verified all returned IDs, and left zero smoke Weddings afterward. It did not create a lasting Auth user or send an external invitation.
